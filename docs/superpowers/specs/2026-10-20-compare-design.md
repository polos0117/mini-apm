# 무엇이 다른가 (고른 요청 vs 나머지 비교)

## 목표

- X-View에서 느린 점을 끌어 고르면, 그 요청들이 나머지와 **어떤 속성에서 다른지**를 표 하나로 본다
  (Honeycomb BubbleUp, Datadog Watchdog Insights 방식).
- 예: "고른 17건 중 85%가 `GET /qna/{id}/list`, 나머지는 12%" → 원인 후보가 바로 위에 온다.
- 대상 앱 코드·Eclipse 설정, Java·Node 에이전트는 그대로.

## 1. 수집 서버

### `POST /compare`

- 본문: `{ ids: string[], since: number, agent: string }`.
  - `ids`: 고른 점의 id. 보관 중(10분)이 아닌 id는 무시한다.
  - `since`: X-View 왼쪽 끝 시각(ms). 숫자가 아니면 0.
  - `agent`: 대시보드에서 고른 앱. 빈 문자열이면 모든 앱.
- 고른 쪽 = `ids` 중 보관 중이고 `agent` 조건에 맞는 트랜잭션.
  나머지 = 끝난 시각(`start + elapsed`)이 `since` 이상이고, `agent` 조건에 맞고, 고른 쪽이 아닌 트랜잭션.
- 응답: `{ picked: n, rest: m, rows: [{ attr, value, picked, rest, pickedPct, restPct }] }`.
  - `picked`·`rest`(행 안): 그 값을 가진 요청 수. `pickedPct`·`restPct`: 0~100 정수(반올림).
  - 차이 `pickedPct − restPct`가 큰 순, 같으면 `picked` 많은 순. 차이(반올림 전 비율 기준)가 10%p 미만이면 뺀다. 15줄까지.
  - 고른 쪽이나 나머지가 0건이면 `rows: []`.
- 본문이 JSON이 아니거나 `ids`가 배열이 아니면 400. 본문 크기 한도는 `/ingest`와 같은 `MAX_BODY`(넘으면 400). 본문 읽기는 `/ingest`와 함께 쓰는 함수로 뺀다.

### 속성 (트랜잭션 하나에서 뽑는 값)

| attr | 값 | 비고 |
|---|---|---|
| `앱` | `agent` | |
| `API` | `route`, 없으면 `name` | API별 통계와 같은 키 |
| `결과` | `에러` / `정상` | `error`가 있으면 에러 |
| `상태` | `status` 숫자를 문자열로, 없으면 `(없음)` | |
| `사용자` | `req.user`, 없으면 `(없음)` | Java 에이전트만 값이 있다 |
| `IP` | `req.ip`, 없으면 `(없음)` | |
| `화면` | `req.referer`의 경로(`URL.pathname`), 없거나 URL이 아니면 `(없음)` | `?` 뒤·호스트는 뺀다 |
| `매퍼` | `mapper` 구간의 `text`(매퍼 ID) | 포함 여부. 한 요청이 같은 매퍼를 여러 번 불러도 1 |
| `외부 호출` | `http` 구간 `text`(`"GET http://host/..."`)의 호스트(`URL.host`), URL이 아니면 `(알 수 없음)` | 포함 여부 |
| `예외` | `exception` 구간 `error`의 `": "` 앞부분, 80자까지 | 포함 여부 |

- 위 세 줄(매퍼·외부 호출·예외)은 그 구간이 있는 요청만 센다. 없다고 `(없음)`을 세지 않는다.
- 값은 200자에서 자른다.

## 2. 대시보드: "무엇이 다른가" 패널

- 위치: 실시간 메뉴, "고른 트랜잭션" 아래·"트랜잭션 상세" 위(`data-tab="live"`).
- X-View에서 영역을 끌어 고를 때마다 `POST /compare`(`ids` = 고른 점 전체, `since` = 지금 − 5분, `agent` = 고른 앱).
- 줄: `속성 | 값 | 고른 쪽 막대 + "85% (17건)" | 나머지 막대 + "12% (40건)"`. 막대는 0~100% 폭, 고른 쪽 파랑·나머지 회색.
  머리글에 `고른 17건 vs 나머지 230건`.
- 비었을 때:
  - 고른 쪽이 0건(이미 정리됨) 또는 나머지가 0건: `비교할 나머지 요청이 없습니다.`
  - `rows`가 빈 배열: `뚜렷한 차이가 없습니다.`
  - 받기 실패: `비교하지 못했습니다(수집 서버 연결 확인).`
- 처음·앱 바꿈·메뉴 바꿈·API 줄 클릭으로 고른 트랜잭션이 바뀌면 패널을 `X-View에서 영역을 끌어 고르면 나머지와 비교합니다.`로 되돌린다.
- 값 칸은 길면 줄바꿈(가로 넘침 없음).

## 테스트

- 수집 서버(`test/` Node):
  - 비율·건수·정렬(차이 큰 순)·10%p 미만 제외·15줄 한도.
  - `(없음)` 값, 화면은 경로만, 외부 호출은 호스트만, 예외는 `": "` 앞, 매퍼 중복 1번.
  - `agent` 조건, `since` 이전 트랜잭션은 나머지에서 제외, 없는 id 무시, 나머지 0건 → 빈 rows.
  - `POST /compare` 정상 응답, 잘못된 본문 → 400.
- 대시보드: Playwright로 X-View를 실제로 끌어 패널 줄·문구 확인, 빈 경우 문구.

## 범위 밖

- 패널 줄을 눌러 고른 트랜잭션을 좁히기, 고른 쪽에 **적은** 값, 숫자 속성(SQL 개수 구간), API 줄 클릭 목록 비교.
