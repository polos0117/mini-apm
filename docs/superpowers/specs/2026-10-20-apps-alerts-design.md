# 앱별로 나눠 보기 + 에러 모아 보기·경보

## 목표

- IP-Finance(`ipfinance`)와 EVL(`evl`)을 한 대시보드에서 골라 보고, '전체'에서는 구분해 본다.
- 최근 에러를 한 패널에 모아 보고, 에러 난 요청과 앱 끊김을 경보로 알린다.
- 성공 기준: 두 앱을 띄운 상태에서 버튼으로 앱을 바꾸면 모든 패널이 그 앱 기준으로 바뀐다.
  한 앱에서 500이 나면 몇 초 안에 알림이 뜨고, 앱을 Eclipse에서 멈추면 10초쯤 뒤 "끊김" 알림이 뜬다.

방식: 수집 서버는 앱 이름을 붙여 보내기만 하고, 거르기와 경보 판단은 대시보드가 한다.
그래서 경보는 대시보드 탭이 열려 있을 때만 울린다(Windows 알림도 같은 전제).
에이전트(Node, Java)는 바꾸지 않는다. 이미 `agent` 이름을 보내고 있다.

## 1. 수집 서버

### 저장소(`collector/store.js`)

- 에이전트 이름 정리: 문자열이 아니거나 앞뒤 공백을 뗀 값이 비면 `unknown`, 40자에서 자른다.
- `ingest`가 저장하는 트랜잭션마다 `tx.agent = 정리한 이름`. 그래서 `/tx/:id` 상세에도 보인다.
- 점(`toPoint`)에 필드 두 개를 더한다.
  - `agent`
  - `msg`: `tx.error`가 문자열이면 200자에서 자른 값, 아니면 `null`. 기존 `error`(불리언)는 그대로.
- 처리 중 항목(`active`)마다 `agent`를 붙인다(받은 객체를 고치지 않고 복사본에).
- `stats(secStart)`는 그대로(전체 합계). `agentStats(secStart)`를 더한다:
  알려진 앱 이름마다 `stats`와 같은 모양 `{ tps, avg, p95, errors }`. 그 1초에 트랜잭션이 없으면 0들.
- `agents(now)`: `[{ name, ago }]`, 처음 데이터를 보낸 순서. `ago = now - 마지막으로 받은 시각`(ms).
  수집 서버가 켜져 있는 동안 한 번이라도 보낸 앱은 빠지지 않는다.
- 처리 중 목록에서 5초(`STALE_MS`) 동안 소식 없는 앱을 빼는 규칙은 그대로.

### 스트림 메시지(`/stream`)

처음 메시지와 매초 메시지 모두 같은 모양:

```
{ points, stats, agentStats, agents, active }
```

## 2. 대시보드

### 앱 버튼과 거르기

- 맨 위에 [전체] + `agents` 순서대로 앱 버튼. 고른 값은 `localStorage`에 기억한다(읽기·쓰기 실패 시 '전체').
  기억한 앱이 목록에 없으면 버튼이 생길 때까지 그 값을 유지하되 화면은 비어 보인다.
- 끊긴 앱(`ago`가 끊김 기준 초과) 버튼에는 빨간 점.
- 앱을 고르면 다음이 그 앱만 보여 준다. 다시 연결하지 않고 화면에서 거른다.
  - 타일(`agentStats[앱]`, 없으면 0들)
  - X-View 점과, 끌어서 고르는 목록
  - 처리 중 목록
  - 최근 에러 패널
- '전체'일 때:
  - X-View 점 모양을 앱마다 다르게(`agents` 순서로 ●, ▲, ■, ◆ 반복). 색은 지금처럼 정상 파랑, 에러 빨강.
    X-View 제목 옆에 범례(모양 + 앱 이름).
  - 고른 트랜잭션·처리 중·최근 에러 목록의 이름 앞에 `[앱]`.

### 최근 에러 패널

- 위치: X-View·처리 중 아래, 고른 트랜잭션 위.
- 화면이 가진 5분치 점 가운데 `error`인 것, 최신순 50줄까지.
- 열: 시각, 앱, 이름, 에러 메시지(`msg`, 한 줄로 자르고 전체는 툴팁). 줄을 누르면 트랜잭션 상세가 열린다.
- 없으면 "없음".

### 경보 판단(`dashboard/alerts.mjs`)

브라우저 API를 쓰지 않는 순수 함수로 두고 단위 테스트한다. 고른 앱과 상관없이 모든 앱을 본다.

```
createAlerts() → { check(msg, now, opts) → 경보 배열, reset() }
opts = { errors: boolean, down: boolean, downMs: number }
경보 = { kind: 'error' | 'down' | 'up', agent, text }
```

- 연결(또는 다시 연결) 뒤 첫 메시지는 기준선으로만 쓴다. 그 메시지의 점으로는 에러 경보를 내지 않고,
  그때 이미 끊겨 있던 앱은 끊긴 상태로 기억만 한다(알리지 않음). 대시보드는 `EventSource`의 `onopen`마다
  새 `createAlerts()`를 만들지 않고 `reset()`을 부른다.
- 에러: 새 점 중 `error`인 것마다. 같은 `agent` + `name`이면 마지막 에러 경보에서 60초 안에는 다시 내지 않는다.
  문구 `[evl] POST /kipa-eval-manage/save — HTTP 500` (`msg`가 없으면 ` — ` 이하 생략).
- 끊김: `agents`의 각 앱에 대해 `ago > downMs`이고 아직 끊김으로 기억하지 않았으면 경보
  `[evl] 끊김 — 10초째 소식 없음`(초는 `downMs/1000` 반올림). 끊김으로 기억한 앱이 `ago <= downMs`가 되면
  `[evl] 다시 연결됨`. 처음 보는 앱은 끊김 아님으로 시작한다(기준선 메시지 제외).
- 꺼 둔 조건은 경보를 내지 않는다. 끊김 경보를 꺼도 끊김 상태 추적은 계속한다(다시 켰을 때 엉뚱한 경보가 없게).

### 알리기

- 맨 위 빨간 줄: 확인하지 않은 경보 중 최근 5개(`시각 문구`)와 [확인] 버튼. 확인하면 줄이 사라진다.
- 확인하지 않은 경보가 있으면 탭 제목 `(⚠N) 미니 APM`.
- Windows 알림: `Notification.permission === 'granted'`이고 `!document.hasFocus()`일 때만 `new Notification('미니 APM', { body: 문구 })`.
- 설정 줄(`localStorage`, 실패해도 기본값으로 동작):
  ☑ 에러 경보  ☑ 끊김 경보  끊김 기준 [10]초  [알림 켜기]
  - 끊김 기준은 1~600초 정수. 그 밖이거나 숫자가 아니면 10.
  - [알림 켜기]는 `Notification.requestPermission()`. 이미 허용됐으면 "알림 켜짐", 거절됐으면 "알림 차단됨(브라우저 설정)"으로 바뀐다.
    `Notification`이 없는 브라우저에서는 숨긴다.
- 화면에 넣는 글자는 모두 `textContent`(기존 테스트 규칙).

## 테스트

- `test/store.test.js`
  - `tx.agent`가 붙고, 이름 정리(비문자열·공백 → `unknown`, 41자 → 40자)
  - 점에 `agent`, `msg`(200자 자름, 에러 없으면 `null`)
  - 처리 중 항목에 `agent`
  - `agentStats`가 앱별로 나뉨, 트랜잭션 없는 앱은 0들
  - `agents`의 순서와 `ago`, 오래된 앱도 남음
- `test/collector.test.js`: 스트림 첫 메시지에 `agentStats`, `agents`, 점의 `agent`가 있다.
- `test/alerts.test.mjs`
  - 기준선 메시지의 에러 점은 무시
  - 새 에러 점 → 경보, 60초 안 같은 `agent`+`name`은 한 번, 다른 앱이나 61초 뒤는 다시
  - `ago`가 기준을 넘으면 끊김 한 번, 돌아오면 다시 연결됨 한 번
  - 기준선에서 이미 끊긴 앱은 조용하고, 돌아오면 다시 연결됨
  - `errors:false`/`down:false`면 해당 경보 없음
  - `reset()` 뒤 첫 메시지는 다시 기준선
- 화면: Playwright 스크린샷으로 확인. 데모 샘플 앱을 `APM_AGENT`가 다른 두 개로 띄워 버튼, 모양 구분, 거르기,
  최근 에러, 빨간 줄을 본다. 하나를 끊어 끊김 경보를 본다. Windows 알림 자체는 사람이 확인한다.
