# 대시보드 개편 (추이선 · 액티브 이퀄라이저 · 관제판 배치)

## 목표

- 숫자 타일 4개(TPS·평균·p95·에러)에 최근 5분 추이선을 붙여 '흐름'이 보이게 한다.
- 제니퍼의 액티브 서비스 이퀄라이저: 앱마다 처리 중 요청을 경과 시간 구간별 색 막대로 쌓는다.
- 배치를 '위는 지금, 아래는 파고들기'(관제판형)로 바꿔 1920×1080 첫 화면에 실시간 위젯이 다 들어오게 한다.
- 색 구성은 지금 남색 테마 그대로(간격·글자만 정리).
- Java·Node 에이전트, 대상 앱 코드·Eclipse 설정은 그대로.

## 1. 수집 서버

### 연결 첫 메시지의 `series`

- `/stream`에 연결하면 첫 메시지(지난 5분 점과 같은 메시지)에 `series`를 더 싣는다.
  ```
  series: {
    all:     [{ sec, tps, avg, p95, errors }, ...],   // 300개
    byAgent: { [앱 이름]: [{ sec, tps, avg, p95, errors }, ...] }  // 앱마다 300개
  }
  ```
- `sec`: 그 1초의 시작 시각(ms). 마지막 원소의 `sec`는 그 메시지의 `sec`(아래)와 같고, 앞으로 1초씩 299개 거슬러 간다(오래된 것부터).
- 각 1초의 값은 지금 타일과 같은 `summarize`로 계산한다(끝난 시각 `start + elapsed`가 그 1초 안인 트랜잭션). 요청이 없던 1초는 `{ tps: 0, avg: 0, p95: 0, errors: 0 }`.
- `byAgent`의 앱 목록은 `agentStats`와 같다(본 적 있는 앱 전부).
- 보관 중인 트랜잭션을 한 번만 훑어 초별로 나눈다(300번 훑지 않는다).
- 이후 1초마다 보내는 메시지에는 `series`를 싣지 않는다.

### 모든 메시지의 `sec`

- 모든 스트림 메시지에 `sec`(그 메시지의 `stats`·`agentStats`가 가리키는 1초의 시작 시각, 지금 `statSec(now)`)를 싣는다.

## 2. 대시보드

### 추이 기록

- 대시보드는 전체·앱별로 `{ sec, tps, avg, p95, errors }` 목록을 갖는다.
- `series`가 온 메시지: 목록을 통째로 바꾼다(다시 연결된 경우 포함).
- 매 메시지: `stats`를 전체 목록에, `agentStats`의 각 앱을 그 앱 목록에 붙인다. 마지막 원소와 `sec`가 같으면 덮어쓰고, 작으면 버린다. 300개가 넘으면 앞에서 버린다.

### 계산 함수 (`calc.mjs`)

- `equalize(active, names)` → `[{ name, counts: [n0, n1, n2, n3], total }]`
  - `names` 순서대로, 요청이 없는 앱도 `counts: [0,0,0,0]`로 포함.
  - 구간: `elapsed < 1000` → 0, `< 3000` → 1, `< 8000` → 2, 나머지 → 3.
  - `names`에 없는 앱의 처리 중 요청은 무시한다.
- `sparkPoints(values, w, h)` → SVG `points` 문자열(`"x,y x,y ..."`)
  - x: 0~w에 고르게(값이 1개면 x=w 한 점). y: 0을 바닥(h), 그 목록의 최대값을 천장(0)으로. 모든 값이 0이면 바닥에 평평한 선. 좌표는 소수 1자리.
  - 빈 배열 → `""`.

### 배치 (관제판형)

| 줄 | 왼쪽 | 오른쪽 |
|---|---|---|
| 1 | 숫자 타일 4개 + 각 타일 아래 5분 추이선 | |
| 2 | X-View (높이 320px) | 340px 칸: 액티브 이퀄라이저(위), 처리 중 목록(아래) |
| 3 | 최근 에러 (전체 폭, 최대 높이 160px) | |
| 4 | 고른 트랜잭션 + 무엇이 다른가 | 트랜잭션 상세 |

- [API별 통계] 메뉴: API 표는 전체 폭, 그 아래 4줄과 같은 좌우(고른 트랜잭션 | 상세).
- 창 폭 1200px 미만: 4줄을 세로 한 칸으로.
- 1920×1080 창(브라우저 화면 영역 약 1920×950)에서 2줄(X-View·처리 중)의 아래 끝이 스크롤 없이 보인다.

### 추이선

- 타일 숫자 아래 SVG(높이 28px, 폭은 타일 폭), 선은 그 타일 색 띠(`--c`)와 같은 색, 선 아래는 같은 색 옅게 채운다.
- 앱 버튼으로 앱을 고르면 그 앱의 목록으로, 전체면 전체 목록으로 그린다.
- 타일 숫자의 느림 색(노랑 ≥1000ms, 빨강 ≥3000ms)은 지금 그대로.

### 액티브 이퀄라이저

- 앱마다 세로 막대 하나. 아래부터 1초 미만(초록 `--good`)·1~3초(파랑 `--ok`)·3~8초(노랑 `--warn`)·8초 이상(빨강 `--err`)을 쌓는다.
- 막대 위에 건수(`total`), 아래에 앱 이름.
- 높이: 가장 많은 앱의 `total`과 5 중 큰 값이 막대 전체 높이(100%).
- 앱 순서는 앱 버튼과 같은 순서(`agents`). 앱을 고르면 그 앱만. 끊긴 앱(앱 버튼에 ● 표시되는 앱)은 흐리게 하고 이름 뒤에 ●.
- 패널 제목 옆에 네 색 범례.
- 앱이 하나도 없으면 `연결된 앱 없음`.

### 디자인 정리 (남색 테마 유지)

- 패널 간격·안쪽 여백을 한 값으로 맞춘다.
- 타일 숫자·패널 제목의 크기와 굵기를 정리한다.
- 표 머리줄(`th`)을 본문보다 진하게 구분한다.
- 색 변수(`--ok`, `--err` …)와 구간 종류 색은 바꾸지 않는다.

## 테스트

- 수집 서버(`test/` Node):
  - `series`: 300개, 마지막 `sec` = 메시지 `sec`, 초 경계(끝난 시각이 정확히 1초 시작인 것은 그 1초), 요청 없는 1초는 0, 300초보다 오래된 트랜잭션 제외, 앱별 목록.
  - 스트림 첫 메시지에 `series`와 `sec`, 다음 메시지에는 `sec`만.
- `calc.mjs`: `equalize` 경계(999·1000·2999·3000·7999·8000ms), 요청 없는 앱, 목록에 없는 앱 무시. `sparkPoints` 빈 배열, 값 1개, 모두 0, 최대값이 천장.
- Playwright: 1920×1080에서 2줄 아래 끝이 첫 화면 안, 1000px 폭에서 4줄 세로, 추이선 `points`가 비어 있지 않음, 이퀄라이저 막대·건수·범례, 페이지 오류 없음.

## 범위 밖

- 추이선에 마우스를 올려 값 보기, 이퀄라이저 막대를 눌러 앱 고르기, 밝은 테마, 새 데이터(JVM·DB 풀).
